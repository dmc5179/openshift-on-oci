# Plan: retire the non-FIPS OC3 cluster and roll out a FIPS cluster

**Status:** draft, 2026-11-12. Nothing in Phases 1–3 has run. Each destructive step needs Dan's
explicit OK.

**Goal:** rebuild `ocp-deployment` in OC3 as a **FIPS** cluster, disconnected exactly as
before (mirror registry, `NeverContactSource`, NTP from IMDS, existing network reused), and
compare it with the non-FIPS results.

## FIPS from a non-FIPS bastion (decided)

`ocibastion` stays non-FIPS. The installer's host check is bypassed with
`OPENSHIFT_INSTALL_SKIP_HOSTCRYPT_VALIDATION=1`:

- **Product docs:** 4.22 *Installation overview*, ch. 4, requires the installer to run "from a
  RHEL 9 computer that is configured to operate in FIPS mode". The bypass isn't documented
  there.
- **Installer source:** `pkg/types/validation/installconfig.go` (release-4.22). If the host
  check fails and the variable is set, the installer logs a warning, continues, and annotates
  the install-config with `install.openshift.io/hostcrypt-check-bypassed: "true"`. The
  installer's `docs/security-guidelines.md` says it "should only be used in testing".
- **What that means:** the nodes boot RHCOS in FIPS mode (`fips: true`) and run the validated
  RHEL crypto. The cluster's initial certificates and keys are generated by the installer on the
  non-FIPS bastion, so this install is **unsupported**, and its starting PKI isn't
  FIPS-generated. Fine for testing; a real DIA or enclave install needs a FIPS-enabled RHEL 9
  host.
- **Verified 2026-11-12 on the bastion:** `openshift-install-fips` 4.22.22, extracted from the
  mirror, refuses `fips: true` without the variable ("target cluster is in FIPS mode, enable
  FIPS mode on the host"). With it, it warns, generates the manifests, and writes the bypass
  annotation. The bastion's RSA SSH key passes the FIPS key rules (ed25519 would be rejected).
- The variable must be set for **every** installer command that loads the install-config:
  `agent create image` and `agent wait-for`.
